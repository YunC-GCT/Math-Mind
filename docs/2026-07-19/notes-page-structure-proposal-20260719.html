笔记页结构优化视觉稿

目标是让 Notes 页保持“学科目录”的清晰定位：首屏负责总览学科结构、数量分布和学科入口；进入学科后再按五类筛选并展示笔记列表。

一、建议结论

当前结构可以保留，但要调整重心

当前合入后的 Notes 页已经有“学科首页”和“学科详情页”，这是合理方向。一级页不需要重复首页的最近笔记能力，应该专注于学科结构和整体统计。

建议一级页使用一个低高度概览块，把核心数字和学科分布合并展示，再接紧凑学科入口。学科区提供“列/块”视图切换；二级页继续保留类型筛选，但列表样式改为统一 NoteCard。

不建议现在继续改详情页

详情页需要重新规划数据结构、公式渲染和五类模板。Notes 页入口先稳定后，再处理详情页更清楚。否则会在列表和详情两边同时重构，验收边界会变模糊。

不动 OCR不动分类 Agent不改数据库只改 Notes 前端结构

三、结构对照

位置当前建议原因
一级 Notes 页 NotesHeader + SubjectGrid NotesHeader + NotesSummaryPanel + SubjectList 一级页负责学科结构总览，不重复首页“最近笔记”的职责。
学科入口 两列大卡片，固定 142 高 默认块视图，允许切换为列表视图 块视图适合总览，列表视图适合学科多时快速扫描。
视图切换 当前固定两列宫格 增加 列 / 块 切换，默认块视图 不同笔记数量下需要不同密度，切换按钮比新增页面更轻。
学科概览 当前没有独立概览，只显示学科卡片 把总数、学科数、本周新增和学科占比分布合并为一个低高度概览块 一级页保持目录属性，同时用最少空间交代知识结构。
学科详情列表 自定义简略行 复用 shared/components/NoteCard.ets 统一标题、类型、日期、置信度和正文预览的展示方式。
类型筛选 横向标签 保留横向标签，增加数量和当前学科概览 五类筛选有价值，但需要先交代当前学科整体状态。

四、实现路线

P0 修正 Notes 相关中文乱码注释和显示字符串，确保页面文本可读。
P1 新增 NotesSummaryPanel，用三项数字、分布条和短图例合并展示全部笔记、学科分组、本周新增和学科分布。
P2 把 SubjectCard 改为更紧凑的学科入口，并增加 SubjectViewToggle 支持列/块切换。
P3 让 SubjectNoteList 复用全局 NoteCard，统一笔记行样式。
P4 完成 smoke test 后，再进入笔记详情页新结构规划。

五、验收标准

视觉验收

首屏同时看到标题、低高度概览块、列/块切换和至少 3 个学科入口。

交互验收

点击学科进入二级页；列/块切换只改变一级页学科入口密度；一级页不出现最近笔记入口。

边界验收

0 条笔记仍显示空状态；只有 1 门学科时不显得空；长学科名和长标题必须省略。
