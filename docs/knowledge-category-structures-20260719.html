MathMind KnowledgeModel 五类结构化输出

生成日期: 2026-07-19。依据当前代码: agents/src/main/ets/agents/KnowledgeModel.ets、KnowledgeUnitExt.ets、KnowledgeCategory.ets、NoteSectionParser.ets。

当前实现结论

KnowledgeModel 按五类知识生成统一 JSON: category、title、tags、difficulty、importance、fields。五类的差异主要体现在 fields 里每个结构化字段的 key。

随后程序不会把 fields 原样落库，而是转换成 KnowledgeUnit.content: 每个字段变成一段 ## label 加正文，最后追加 ## 原文。

一、统一输入输出骨架

LLM 原始返回 AiRawResponse

{
  "category": "概念 | 定理 | 公式 | 证明题 | 计算题",
  "title": "知识点标题或题目摘要",
  "tags": ["标签1", "标签2"],
  "difficulty": 1,
  "importance": 1,
  "fields": [
    {
      "key": "definition",
      "label": "定义",
      "value": "字段内容, 可以包含公式"
    }
  ]
}

落库前主线 KnowledgeUnit

{
  "id": "KB-...",
  "title": "来自 AiRawResponse.title",
  "content": "## 字段标题\\n字段内容\\n\\n## 原文\\nOCR 原文",
  "summary": "从 fields.value 拼接并截断到约 100 字",
  "tags": ["category", "...AI tags"],
  "difficulty": "DifficultyLevel",
  "source": "chapter 或 camera_capture",
  "reviewStatus": "new",
  "nextReviewAt": "创建时间 + 1 天",
  "intervalDays": 1,
  "easeFactor": 2.5,
  "repetitions": 0
}

实现注意点

当前 KnowledgeCategory 类型定义是中文五类，但 buildPrompt() 文案要求模型返回 concept/theorem/formula/proof/computation。如果模型真的返回英文，运行时会把英文值作为 category 写入 tags 和 content 生成链路。建议后续统一为中文输出，或在 callAi() 后增加 category normalize。

二、五类字段结构

概念 prompt key: concept 适合定义、性质、例子、关联概念
keylabel 建议value 内容
definition定义概念的严格定义、条件和符号说明。
properties性质核心性质、常用结论、使用限制。
examples例子能帮助理解的典型例子或反例。
related_concepts相关概念前后关联概念、容易混淆的概念。
定理 prompt key: theorem 适合定理、引理、命题、推论
keylabel 建议value 内容
statement定理陈述完整定理内容。
conditions条件成立前提、定义域、连续性、可导性等限制。
conclusion结论定理推出的核心结果。
proof_sketch证明思路简要证明路线、关键构造或关键不等式。
applications应用常见用途、典型题型、可关联知识点。
公式 prompt key: formula 适合公式整理、恒等式、变形规则
keylabel 建议value 内容
expression公式公式主体，重要公式单独成行。
parameters参数说明变量、常量、符号含义。
applicable_range适用范围公式成立条件、定义域、边界条件。
derivation推导简要推导过程或来源。
notes备注易错点、等价形式、记忆提示。
证明题 prompt key: proof 适合求证题、证明过程整理
keylabel 建议value 内容
proposition命题需要证明的结论。
given已知条件题目给定条件和可用前提。
proof_process证明过程分步骤证明，保留关键逻辑链。
key_insight关键思路突破点、构造方法、所用定理。
conclusion结论证明完成后的总结。
计算题 prompt key: computation 适合计算、求解、化简、求极限等
keylabel 建议value 内容
problem题目题目条件和要求。
steps步骤分步计算过程。
answer答案最终结果，尽量单独成行。
method_summary方法总结本题使用的方法、套路或算法。
common_mistakes易错点常见错误、检查点、符号陷阱。

五、需要后续修正的程序点

1统一 category 语言。当前类型是中文，prompt 是英文枚举。

2保留 subject。当前 KnowledgeModel 只把 subject 当 hint，不会稳定写入 tags，导致 UI 的 subject/type 映射可能错位。

3如果未来需要编辑结构化字段，RDB 需要新增字段保存原始 fields JSON。当前只保存拼接后的 content。

六、当前前端如何渲染这些类别

1. 列表卡片 NoteCard

首页和笔记页最终都渲染 NoteItem，不是直接渲染 KnowledgeUnitExt.fields。当前 NoteCard 展示四块信息:

位置数据来源当前效果
左侧图标typeChar(note.type)取类型首字作为图标文字，例如 概、计、证。
颜色typeColor(note.type)只有 概念、计算、证明、笔记 有明确配色。
Meta 行note.type、note.date、note.conf显示 类型 · 时间 · 置信度百分比。
正文预览note.body显示 KnowledgeUnit.content 前两行截断，可能直接露出 ## 定义 等分段标题。

实际文件: entry/src/main/ets/shared/components/NoteCard.ets、common/src/main/ets/data/MockNotes.ets。

2. NoteItemMapper 的关键问题

当前 KnowledgeModel.buildTags() 生成的 tags 顺序是 [category, ...AI tags]。但 NoteItemMapper 读取时使用:

const subject = unit.tags.length > 0 ? unit.tags[0] : "数学"
const type = unit.tags.length > 1 ? unit.tags[1] : "笔记"

这会让五类渲染错位。例如一个计算题的 tags 如果是 ["计算题", "极限", "数学分析"]，前端会得到:

subject = "计算题"
type = "极限"

结果是列表卡片不会显示“计算题”，颜色也无法命中 typeColor()，最终走默认红色。

3. 详情页 NoteDetailOverlay

详情页当前是通用渲染，不区分五类专用布局:

区域实际逻辑对五类的影响
顶部标题优先显示 unit.title五类统一，没有问题。
Meta 标签tags[0] 为主标签，tags[1] 为次标签依赖 tags 顺序，当前容易把类别当学科。
摘要显示 unit.summary来自 fields.value 拼接后的前 100 字，类别信息不明显。
正文NoteSectionParser 按 ## 切章节不同类别只是章节标题不同，没有图标、顺序、重点样式差异。
标签/前置/相关/来源/复习统一块状渲染不会根据“证明题/计算题”等给出专门操作。

实际文件: NoteDetailOverlay.ets、NoteDetailMeta.ets、NoteDetailBody.ets、NoteSectionParser.ets。

七、当前渲染问题

问题 1五类没有完整配色。typeColor() 不认识 定理、公式、证明题、计算题，而 mock 里还是旧的 计算、证明。

问题 2类别和学科没有独立字段。类别、学科、章节都挤在 tags/source，前端只能猜。

问题 3详情页丢失结构化字段语义。fields 落库后变成纯文本分段，UI 无法知道某段是 answer、proof_process 还是 common_mistakes。

问题 4列表预览可能读起来不自然。因为 note.body 直接来自 content，预览可能以 ## 题目、## 定义 开头，而不是更干净的摘要。

问题 5五类没有差异化学习动作。计算题没有“看答案/重做”，证明题没有“隐藏证明过程”，公式没有“参数速查”。

八、建议和改进方法

短期修正: 不改表结构也能做

改进方法收益
统一五类名称 把 KnowledgeModel.buildPrompt() 的 category 输出改成中文五类，或新增 normalizeCategory() 把英文映射到中文。 避免 tags、标题、卡片颜色出现英文 category。
修正 NoteItemMapper 按五类集合识别 type，按学科关键词或独立规则识别 subject。不要固定 tags[0] 是 subject。 首页/笔记列表能正确显示“计算题/证明题/定理”等类型。
补齐 typeColor/typeChar 支持 概念、定理、公式、证明题、计算题，兼容旧值 计算、证明。 五类在卡片上有稳定视觉编码。
列表预览优先用 summary unitToNoteItem() 中 body 优先取 summary，详情页再使用 content。 卡片预览更像摘要，不被 Markdown 标题干扰。

中期改进: 增加类别感知渲染

类别详情页建议布局交互建议
概念定义置顶，性质和例子并列，相关概念放底部。提供“生成例题”“对比相似概念”。
定理条件 → 结论 → 证明思路 → 应用，突出条件和结论。提供“隐藏证明”“只背条件/结论”。
公式公式大字号展示，参数说明紧随其后，备注放底部。提供“复制公式”“查看推导”。
证明题命题和已知条件固定在顶部，证明过程分步编号。提供“逐步展开证明”“隐藏关键思路”。
计算题题目 → 步骤 → 答案，答案视觉上单独强调。提供“先隐藏答案”“重做此题”。

长期改进: 保留结构化字段

建议把 KnowledgeUnit 扩展为带结构化元数据的形态，或者在 RDB 增加 category、subject、chapter、fields_json 字段。这样 UI 不需要从 tags 和 Markdown 文本中反推语义。

knowledge_unit 新增建议:
category TEXT NOT NULL DEFAULT ""
subject TEXT NOT NULL DEFAULT ""
chapter TEXT NOT NULL DEFAULT ""
fields_json TEXT NOT NULL DEFAULT "[]"
truth_flag INTEGER NOT NULL DEFAULT 1
truth_details TEXT NOT NULL DEFAULT "[]"

前端则新增 StructuredNoteView，根据 category 选择渲染模板。对五类笔记，详情页只展示结构化字段；原文、OCR、默认 内容 旧正文会被过滤，不再作为详情正文展示，也不再转换成“识别公式/识别原文”。

概念
极限的 ε-δ 定义
数学分析 极限 定义 New

定义

若对任意 ε > 0，存在 δ > 0，使得当 0 < |x-a| < δ 时，有 |f(x)-L| < ε，则称 f(x) 在 a 处的极限为 L。

性质

极限若存在则唯一；局部有界；满足保号性和四则运算。

例子

lim(x→0) sin x / x = 1 可以用夹逼定理证明。

相关概念

函数连续、数列极限、夹逼定理、无穷小。

定理陈述

若 f 在 [a,b] 上连续，在 (a,b) 内可导，则存在 ξ∈(a,b)，使得:

f'(ξ) = (f(b)-f(a))/(b-a)

条件

闭区间连续；开区间可导；a < b。

结论

某一点的瞬时变化率等于区间平均变化率。

证明思路

构造辅助函数，把端点函数值拉平，然后使用罗尔定理。

命题

若向量组 α1,...,αn 线性无关，则它的任意子组也线性无关。

已知条件

原向量组线性无关。

证明过程

  1. 取任意子组 αi1,...,αik。
  2. 设 c1αi1 + ... + ckαik = 0。
  3. 把未出现向量的系数补为 0，得到原向量组的线性组合。
  4. 由原组线性无关，所有系数均为 0。

关键思路

把子组的线性组合扩展回原向量组。
