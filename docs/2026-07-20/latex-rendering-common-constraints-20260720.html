MathMind LaTeX 文本风险处理方案

适用范围：AI 对话、笔记生成、笔记详情页、首页/学科块小字预览。目标不是新增跨模块公共协议，而是在现有 KaTeX 渲染路线前增加一层轻量风险处理：生成时规避高危格式、渲染前实时订正明确错误、无法确认语义时降级兜底展示。

2026-07-20 · Risk Guard
风险规避 让 LLM 尽量输出 KaTeX 友好的 Markdown + LaTeX，减少裸反斜杠、嵌套美元符号和半截公式。
实时订正 渲染前只修复语义明确的格式问题，例如裸展示公式补 delimiter、`, dx` 改成 `\,dx`。
兜底降级 括号缺失、命令拼错、公式结构不完整时，不猜数学语义，保留源码或走普通文本展示。
稳定观感 避免红色错误文本、美元符号外露、反斜杠残留和公式 WebView 闪烁，同时保留横向滚动。

1. 处理目标

阶段 主要风险 处理策略
AI 输出 裸 LaTeX、display math 中嵌套 `$...$`、把公式拆成多行半截文本。 用 prompt 规避高危格式，但不依赖一个共享协议文件；失败时交给渲染前修正层兜底。
数据库文本 旧笔记或 OCR 文本里可能已有不规范 LaTeX。 数据库只保存源文本；不保存 HTML。进入 UI 渲染前按当前内容即时修正，不批量改历史数据。
渲染前处理 KaTeX 对 delimiter、括号、命令拼写很敏感，错误会显示红色源码。 做轻量 normalize：补明确 delimiter、移除 display 内部嵌套美元、修正常见微分空格。
KaTeX 渲染 复杂公式过宽、解析失败、测量高度延迟。 公式交给 KaTeX；宽公式只保留横向滚动；缓存已渲染 HTML 与高度，减少再次进入时的闪烁。
兜底展示 无法确定用户原始数学意图时，自动修复可能改错公式。 不补语义、不猜分母、不改变量；保留原文、显示普通文本或局部降级，保证页面不炸。

2. 高风险文本形态

低风险行内公式

短变量、短条件、句内数学对象使用 `$...$`，可以稳定进入 KaTeX。

积分变量为 $x$，积分常数为 $C$。
当 $n \neq -1$ 时公式成立。

裸反斜杠风险

裸命令可能被 Markdown 当普通文本，也可能被错误切成多个行内公式。

积分变量为 \x，积分常数为 \C。
当 \n \neq -1 时公式成立。

低风险展示公式

复杂公式单独成行，使用 `$$...$$` 包住完整表达式。

$$
\int x^n\,dx = \frac{x^{n+1}}{n+1} + C \quad (n \neq -1)
$$

嵌套 delimiter 风险

外层已经是展示公式时，内部 `$...$` 会破坏 KaTeX 自动渲染。

\int x^n, dx = \frac{x^{n+1}}{n+1} + C \quad ($n \neq -1$)

3. 实时订正规则

输入风险 可自动订正 边界
整行以 `\int`、`\sum`、`\lim`、`\frac`、`\sqrt` 开头但没有 delimiter。 \int x^n dx → $$\int x^n dx$$ 只处理整行或明显等式，不处理夹在长中文段落中的不完整片段。
展示公式内部嵌套 `$n \neq -1$`。 \quad ($n \neq -1$) → \quad (n \neq -1) 只删除 delimiter，不改变条件内容。
积分末尾使用普通 `dx` 或 `, dx`。 , dx → \,dx 只处理常见微分符号，不重写积分上下限和被积函数。
独立的 `[` / `]` 被模型当作公式边界。 [ → \[，] → \] 只在独立成行时转换，避免误改普通列表文本。
中文段落里出现裸 `\mu`、`\sigma`、`\theta` 等短符号。 均值为 \mu → 均值为 $\mu$ 只处理短符号和明确比较式，不把整段中文包进公式。

4. 生成阶段风险规避提示

这段适合保留在 AgentChatService 或 KnowledgeModel 的 system prompt 中，目标是降低后续订正压力。

LaTeX 文本风险规避：
1. 行内短公式必须写成 `$...$`，例如 `$x$`、`$C$`、`$n \neq -1$`。
2. 独立复杂公式必须写成 `$$...$$`，例如 `$$\int x^n\,dx = ...$$`。
3. 不要输出裸 LaTeX 命令行，例如不要直接输出 `\int ...`、`\frac ...`。
4. 不要在 `$$...$$` 内再写 `$...$`。
5. 公式条件放在同一个公式环境里，例如 `\quad (n \neq -1)`。
6. 文本解释和公式分开：先写一句说明，再写展示公式。
7. 如果不确定公式是否完整，保留原题文字，不要补造缺失的数学结构。

5. 渲染前兜底流程

先做轻量修正

只修复不会改变数学含义的问题，让 KaTeX 尽量接收到完整公式。

\int x^n, dx = ... ($n \neq -1$)
→
$$\int x^n\,dx = ... \quad (n \neq -1)$$

再做降级兜底

括号不闭合、命令拼错、公式语义缺失时，UI 不猜测数学意图。

$$
\frac{x+1
$$

处理：保留原文或显示错误态，不能自行补分母。

6. 公式完整渲染补充

补充点 处理要求 原因
整式进入 KaTeX 分式、根号、上下标、积分上下限、极限下标、矩阵、分段函数必须作为一个完整公式字符串进入 KaTeX，不能被 Markdown 段落、空行或多个 WebView 拆开。 拆开后会导致等号两侧不对齐、根号长度不完整、上下标位置错误、括号高度不匹配。
展示公式优先 包含 \frac、\sqrt、\lim、\sum、\int、\begin、\left、\right 的复杂表达式优先转为 display math。 手机端宽度有限，复杂公式放在行内会压缩文本、触发行高错乱或显示不完整。
归一化顺序 先统一换行，再保护代码块，再识别已有 $...$、$$...$$、\(...\)、\[...\]，最后只对未被包裹的裸公式做订正。 避免把已经正确的公式重复包裹，也避免误改代码块、普通数组或 Markdown 链接。
幂等性 同一段文本多次经过渲染前处理，结果必须一致：不能出现 $$$$...$$$$、$$$\mu$$$ 或重复插入 \,dx。 缓存、详情页重复进入、列表预览复用同一文本时都依赖处理结果稳定。
局部失败 一条消息里只有某个公式失败时，只降级该公式或该段落；其他公式继续渲染，不把整条 AI 回复全部退回纯文本。 保证长解答中的可用公式尽量完整呈现，降低单个坏公式对整体阅读的影响。

7. 完整渲染样例

类型 推荐源文本 验收重点
正态分布 $$f(x)=\frac{1}{\sigma\sqrt{2\pi}}\exp\left(-\frac{(x-\mu)^2}{2\sigma^2}\right)$$ 等号左右同一基线；根号覆盖完整 2\pi；指数中的分式、括号和上下标位置正确。
极限 $$\lim_{x \to 0}\frac{\sin x}{x}=1$$ x \to 0 必须位于 lim 下方或紧贴下标位置，分式不能被拆成普通文本。
定积分 $$\int_a^b f(x)\,dx = F(b)-F(a)$$ 上下限贴合积分号，\,dx 间距正确，横向滚动条只在宽度不足时出现。
分段函数 $$f(x)=\begin{cases}x^2, & x \ge 0\\-x, & x<0\end{cases}$$ 大括号完整覆盖两行，条件列对齐，不出现红色源码。
矩阵 $$A=\begin{pmatrix}1 & 2\\3 & 4\end{pmatrix}$$ 括号高度匹配矩阵行数，单元格对齐，不能被 Markdown 表格或换行拆断。

8. 给 Schema 负责人的需求

需求项 建议字段 说明
保留原始文本 rawText: string 必须能回看 AI/OCR/RDB 传入的原文。订正失败时用它做兜底展示，也便于排查是源文本问题还是渲染问题。
保存渲染前文本 normalizedText: string 这是送入 KaTeX 的文本，经过换行归一化、裸公式补 delimiter、display 内嵌美元清理等轻量处理。缓存 key 应基于这个字段。
风险分级 riskLevel: "none" | "fixable" | "fallback" none 表示可直接渲染；fixable 表示已做确定性订正；fallback 表示存在半截公式、括号不闭合或未知命令，需要降级。
风险明细 issues: string[] 记录命中的风险，例如 bare_display_formula、nested_dollar_in_display、unclosed_brace、unknown_command。
订正明细 fixes: string[] 记录实际做过的处理，例如 wrap_display_delimiter、remove_nested_dollar、normalize_differential_dx。便于定位是否误修。
渲染模式 renderMode: "native" | "katex" | "plainFallback" 普通文本走 native；含可渲染公式走 katex；不可安全修复时走 plainFallback，避免红色 KaTeX 错误污染 UI。
公式块边界 segments: RenderSegment[] 可选字段。用于后续做局部失败降级：文本段、行内公式、展示公式分别标记，单个公式失败时不影响整条消息。
验收样例 fixtures: LatexFixture[] schema 需要能表达正态分布、极限、定积分、分段函数、矩阵这些样例的输入、期望风险级别和期望渲染模式。

建议 Schema 草案

{
  "rawText": "原始 Markdown + LaTeX 文本",
  "normalizedText": "渲染前处理后的 Markdown + LaTeX 文本",
  "riskLevel": "none | fixable | fallback",
  "issues": ["bare_display_formula", "nested_dollar_in_display"],
  "fixes": ["wrap_display_delimiter", "remove_nested_dollar"],
  "renderMode": "native | katex | plainFallback",
  "segments": [
    {
      "kind": "text | inlineMath | displayMath | fallbackText",
      "source": "原始片段",
      "normalized": "处理后片段",
      "safeToRender": true
    }
  ]
}

这份 schema 只服务公式渲染完整性：描述文本是否安全、做过什么订正、应该怎么渲染。它不参与 TypeClassifier 的题型/学科判断，不要求 KnowledgeModel 保存渲染 HTML，也不改变 RDB 的源文本存储原则。

9. 数据流处理点

OCR 只识别文本，尽量保留原始公式字符；不要在 OCR 阶段猜公式结构。
TypeClassifier 只判断题型/学科，不承担公式修复；避免分类影响正文数学内容。
KnowledgeModel 结构化笔记时通过 prompt 规避高危 LaTeX 输出，正文仍保存为 Markdown 源文本。
RDB 保存源文本、分类、学科、标签、复习字段；不保存渲染 HTML 或修复缓存。
UI 渲染前做轻量订正和失败兜底；含公式内容交给 KaTeX，普通文本走 native。

10. 风险复盘

高风险来源：裸展示公式 + 内嵌美元符号
红色原文通常来自这种输入，渲染前可以明确订正：
\int x^n, dx = \frac{x^{n+1}}{n+1} + C \quad ($n \neq -1$)
订正后交给 KaTeX：
$$\int x^n\,dx = \frac{x^{n+1}}{n+1} + C \quad (n \neq -1)$$
高风险来源：段落行内公式没有进入 KaTeX
段落中的 `$x$`、`$C$`、`$n \neq -1$` 需要被公式检测捕获。若检测不到，用户会看到美元符号或反斜杠原文。
不可自动修复：半截公式或命令拼写错误
例如 `\frac{x+1`、`\sqr{x}` 这类输入不能直接猜测为完整公式。正确处理是保留源文本或局部降级，避免把错公式修成另一个错公式。

11. 验收标准

页面 必须通过
AI 对话框 复杂公式不露出反斜杠原文；行内 `$...$` 不显示美元符号；明确可订正的裸公式能在渲染前被修正；公式区域只有横向滚动条。
笔记详情页 正文、摘要、推导段落中的行内公式和展示公式都能渲染；旧数据中的高风险 LaTeX 先经过轻量订正；无法订正时稳定降级展示。
首页笔记小字 包含公式的预览不再显示红色错误文本；普通文本仍走原生截断；公式预览不撑开卡片高度；订正失败时不影响卡片布局。
学科块小字 标题或预览含公式时进入 KaTeX compact preview；风险文本降级后仍不撑开卡片高度。
重复进入同一笔记 第二次进入同一内容时命中进程内缓存；缓存 key 基于渲染前处理后的文本，避免同一风险文本重复修正和重复解析。
结论： 后续判断 LaTeX 问题时先看风险类型：明确格式风险由渲染前轻量订正处理；语义不完整或不确定的公式不自动修复，只做降级兜底；如果订正后的合法文本仍渲染失败，再归为 UI/KaTeX 集成问题。
