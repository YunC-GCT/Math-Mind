ResultSet 越界崩溃原因分析

针对 NoteDao.ets:148 读取 subject 列触发 14800013 的本地代码排查结论。

2026-07-20

一、结论

根因是旧数据库表结构没有迁移。

合入 cmnon159 后，代码认为 knowledge_unit 表一定有 subject 和 category 两列，但旧安装包产生的本地 MathMind.db 里没有这两列。应用查询旧表后，rowToUnit() 调用 rs.getColumnIndex("subject") 得到无效列索引，再传给 getString()，于是触发 Resultset is empty or column index is out of bounds。

二、为什么不是 SELECT 投影问题

查询入口当前查询列判断
NoteDao.queryById() this.store.query(predicates, ['*'], ...) 没有只选 id/title，不是投影漏列。
NoteDao.queryAll() this.store.query(predicates, ['*'], ...) 崩溃栈 NoteDao.ets:107 对应这里循环读取结果。
NoteDao.queryByReviewStatus() this.store.query(predicates, ['*'], ...) 同样不是投影漏列，但也会被旧表结构影响。
日志里的 Resultset is empty 是底层通用错误文案。结合 GetColumnIndex: Failed, columnName: sub*** 和栈位置，实际更符合“列索引不存在”，不是“没有数据行”。

三、触发链路

1. 打开笔记页 页面加载笔记列表，调用 NoteDao.queryAll()。
2. 查询旧表 ['*'] 返回旧表实际存在的列，不包含新增列。
3. 转实体 rowToUnit() 读取 subject/category。
4. 越界崩溃 getColumnIndex("subject") 失败，getString(-1) 抛出 14800013。 
entry/src/main/ets/database/NoteDao.ets

subject: rs.getString(rs.getColumnIndex('subject')),   // 崩溃点
category: rs.getString(rs.getColumnIndex('category')), // 下一处也会有同样风险

四、数据库结构变化

这次合入后，KnowledgeUnit 从 tags 推断学科/类型，升级为独立字段：

common/src/main/ets/models/CommonTypes.ets

subject: string;
category: string;

建表 SQL 也新增了两列：

common/src/main/ets/DatabaseHelper.ets

subject TEXT NOT NULL DEFAULT "",
category TEXT NOT NULL DEFAULT "",
问题在于 CREATE TABLE IF NOT EXISTS knowledge_unit (...) 只会在表不存在时创建新表。如果旧表已经存在，它不会自动追加 subject 和 category。

五、当前迁移逻辑缺口

位置现状问题
DatabaseHelper.ensureSchema() 依次执行 CREATE TABLE IF NOT EXISTS 和索引创建。 不会修补已有表缺失列。
DB_SCHEMA_VERSION = 2 最后只做 if (store.version < 2) store.version = 2。 没有按版本执行迁移 SQL；如果旧库已是 2，也完全跳过。
NoteDao.rowToUnit() 直接读取所有字段。 没有安全读取列；缺列时直接崩溃。
NoteDao.toBucket() 插入/更新时写入 subject/category。 旧表缺列时，新增笔记也可能写入失败。

六、推荐修复方向

必须加数据库迁移

在 DatabaseHelper.ensureSchema() 中补 ALTER TABLE knowledge_unit ADD COLUMN subject... 和 category...。如果列已存在，要识别并忽略重复列错误。

rowToUnit 做兼容读取

新增安全读取函数。列不存在时返回默认值，避免旧库或异常查询直接崩溃。

旧数据回填

旧笔记的 subject/category 为空时，UI 仍通过 tags 推断。后续可以批量回填，但不是阻断修复。

建议迁移 SQL:

ALTER TABLE knowledge_unit ADD COLUMN subject TEXT NOT NULL DEFAULT "";
ALTER TABLE knowledge_unit ADD COLUMN category TEXT NOT NULL DEFAULT "";

七、验收标准

场景操作通过标准
旧数据库升级 不清应用数据，直接安装新包，打开笔记页。 不再出现 14800013，旧笔记能展示。
新建数据库 清空应用数据后首次启动。 knowledge_unit 创建时包含 subject/category。
新增笔记 拍照/选图生成笔记。 插入成功，笔记页能按学科分组，按五类题型筛选。
旧笔记兼容 打开升级前已有的笔记详情。 学科/类型为空时不崩，仍可从 tags 或默认值展示。

八、需要注意的冲突点

后续真正修代码时，主要会碰这几个文件：

文件改动点可能冲突
common/src/main/ets/DatabaseHelper.ets 新增迁移 SQL 和迁移执行顺序。 和后续任何数据库版本升级冲突，必须统一管理 DB_SCHEMA_VERSION。
entry/src/main/ets/database/NoteDao.ets 新增安全读取列函数，替换 subject/category 直接读取。 和后续更多字段入库会冲突，建议一次抽出通用读取方法。
entry/src/main/ets/utils/NoteItemMapper.ets 旧数据字段为空时继续 fallback 到 tags。 当前已经有 fallback，原则上不需要大改。
