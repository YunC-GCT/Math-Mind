当前代码结论

TypeClassifier 当前负责文本暴露 + 轻量分类：文本输入直接返回原文，图片/文件输入调用 OcrTool 后做轻量清洗，再用 LLM 优先识别五类与学科，失败时规则兜底。

KnowledgeModel.structure() 仍保留最终智能判断：它接收 TypeClassifier 的类型/学科作为 hint，但会根据题目内容独立输出最终 subject/category/fields。主线落库模型是 KnowledgeUnit，已包含独立 subject 与 category 字段。

一、当前主链路

1. UI 输入 拍照/相册调用 AiService.capture()；文本入库调用 captureText()。
2. 图片准备 ImageUriResolver.resolve() 把 file URI 复制到沙箱路径。
3. 调度 Dispatcher.dispatch() 统一接收 DispatchRequest。
4. 文本暴露 TypeClassifier.classify() 提取文本并识别五类/学科。
5. 结构化 KnowledgeModel.structure() 参考分类 hint，生成最终五类 JSON 并真值检验。
6. 入库 AiService.insertNote() 使用 NoteDao.insert() 写入 RDB。
7. 展示 NoteItemMapper 转 UI 模型；详情页按 ## 分段渲染。

图片路径

AgentFloatWindow / 页面
  -> AiService.capture(imageUri, userText?)
  -> ImageUriResolver.resolve(imageUri)
  -> Dispatcher.dispatch({ kind: "image", imageUri: localPath })
  -> TypeClassifier.classify()
       -> OcrTool.recognize(localPath)
       -> preprocessText()
       -> LLM 五类/学科识别，失败规则兜底
  -> KnowledgeModel.structure(ocrText, type, subject, chapter)
  -> NoteDao.insert(unit)

文本路径

AgentChatService / 输入框
  -> AiService.captureText(text)
  -> Dispatcher.dispatch({ kind: "text", text })
  -> TypeClassifier.classify()
       -> rawText = payload.text
       -> preprocessText()
       -> LLM 五类/学科识别，失败规则兜底
  -> KnowledgeModel.structure(text, type, subject, chapter)
  -> NoteDao.insert(unit)

二、Agent 边界

模块当前职责明确不做
Dispatcher 主 Agent 调度中枢；负责调用文本识别、处理空 OCR fallback、调用 KnowledgeModel，返回 DispatchResult。 不直接做 LLM 分类，不直接入库。
TypeClassifier 做 recognizeText() 文本提取与清洗；classify() 用 LLM 优先识别五类、学科、章节，失败时规则兜底。 不生成 KnowledgeUnit，不入库。
KnowledgeModel 通过 LLM 自行判断最终 category/subject/title/tags/fields，可参考 TypeClassifier hint，做 truthCheck，并转换为主线 KnowledgeUnit。 不持久化；不直接读写 UI 状态。
NoteDao KnowledgeUnit 与 RDB knowledge_unit 表互转。 不做结构化推理。

四、KnowledgeModel 五类字段

概念定义、性质、示例、相关概念
字段含义
definition严格定义、条件、符号说明。
properties核心性质、常用结论、限制条件。
examples典型例子、反例或帮助理解的场景。
related_concepts相关或易混淆概念。
定理陈述、条件、结论、证明思路、应用
字段含义
statement完整定理、引理、命题或推论内容。
conditions成立前提，如连续、可导、定义域等。
conclusion定理推出的核心结果。
proof_sketch关键证明路线、构造或关键不等式。
applications典型用途、题型或关联知识点。
公式表达式、参数、适用范围、推导、备注
字段含义
expression公式主体，重要公式单独成行。
parameters变量、常量、符号含义。
applicable_range成立条件、定义域、边界条件。
derivation简要推导过程或来源。
notes易错点、等价形式、记忆提示。
证明题命题、已知、证明过程、关键思路、结论
字段含义
proposition需要证明的结论。
given题目给定条件和可用前提。
proof_process分步骤证明，保留关键逻辑链。
key_insight突破点、构造方法、所用定理。
conclusion证明完成后的总结。
计算题问题、步骤、答案、方法总结、常见错误
字段含义
problem题目条件和要求。
steps分步计算过程。
answer最终结果，尽量单独成行。
method_summary本题使用的方法、套路或算法。
common_mistakes常见错误、检查点、符号陷阱。

fields 到 content

summary 与 tags

summaryFromFields()
  -> 依次拼接 fields.value
  -> 去除 # 和 *
  -> 最多约 500 字

buildTags()
  -> 只保留 aiRaw.tags 去重结果
  -> category 写入 unit.category
  -> subject 写入 unit.subject

  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  content TEXT NOT NULL DEFAULT "",

当前工作区 DatabaseHelper 已包含 subject/category 的幂等 ALTER TABLE 迁移；NoteDao.rowToUnit() 也做了缺列安全读取，旧库不会因为缺列直接触发 ResultSet 越界。

七、UI 映射与展示

NoteItemMapper

KnowledgeUnit
  -> rawId: unit.id
  -> subject: unit.subject 优先，空时从 tags 推断
  -> type: unit.category 优先，空时从 tags 推断
  -> chapter: source 非 camera_capture 时用 source，否则用 subject
  -> conf: ReviewStatus 映射到 0.45~0.95
  -> body: 当前代码优先 stripMD(unit.summary)，content 只作 fallback

详情页

NoteDetailOverlay
  -> NoteDetailMeta
  -> NoteDetailBody
       summaryText() 渲染“摘要”
       bodyText() 取 unit.content
       parseSections(bodyText)
       NoteSectionView
       MathTextRenderer

当前详情页是通用分段渲染，不存在独立 StructuredNoteView 或五类专用组件。

类型视觉

NoteTaxonomy 支持五类键：概念、定理、公式、证明题、计算题。旧别名 证明、计算 会归一化。

学科分组

学科优先来自 KnowledgeUnit.subject。只有旧数据缺字段时才从 tags 中寻找非类型、非 camera_capture 标签。

预览注意

当前 NoteItemMapper 列表预览优先取 summary，避免优先露出 ## 定义 这类 Markdown 分段标题。

八、降级路径

场景当前处理结果
图片/文件 OCR 为空 Dispatcher 跳过 KnowledgeModel，调用 buildFallbackUnit("概念", "", "")。 保存标题为“概念 (待补充)”的框架笔记，正文提示人工补充。
文本输入清理后为空 Dispatcher 回落到 payload.text。 仍进入 KnowledgeModel.structure()。
LLM 调用失败或返回空 KnowledgeModel.buildFallbackFromClassify() 使用 OCR 首行或默认类型生成基础 KnowledgeUnit。 不丢原始 OCR/文本，但分类和学科可能为空或默认。
旧数据库缺 subject/category DatabaseHelper 迁移补列；NoteDao 缺列读取返回默认值。 旧笔记可继续展示，新笔记可正常插入。
