一、当前结论

现在公式 UI 观感差，不是数据库问题，也不是 KnowledgeModel 单点问题，而是渲染层仍停在“识别出公式块后用 ArkUI Text 显示 LaTeX 字符串”。所以 \frac、\sqrt、\sum 这些命令不会真正排版，短公式还会被拆成独立块，阅读体验接近 0。

新的视觉原则是：公式默认服务于句子，不默认打断句子。 只有长公式、核心结论、多行推导、矩阵/cases/aligned 这类内容才独立成块。普通符号、变量、短等式、极限条件和简单分式都应优先留在正文段落里。

AI 对话要比笔记详情更克制。 对话里的展示公式不应做成重卡片，而应是透明背景的紧凑公式条；多行推导只保留轻量左线和上下结构，减少背景、边框和大留白。

本文件是最终合并方案，已取代旧的 latex-render-db-ui-guide-20260720.html 和 rich-math-rendering-redesign-20260720.html。后续实现、评审和验收只看本文件，避免两个方案同时存在造成判断分叉。

不改数据库不把 HTML 入库不做手写公式渲染统一 KaTeX

最终判断

应该采用“统一 RichMath 渲染层”，但落地顺序不能直接推翻现有 MarkdownRenderer。当前程序已经有笔记编辑与 Markdown 解析，因此最稳妥的路线是：保留 Markdown 作为外层块解析，新增 RichMath 作为数学内容内核。

这样可以同时解决笔记详情和 AI 对话：笔记继续保留 Markdown 标题/列表/代码块；聊天得到同一套公式混排和 fallback。

5.4 公式块最小化规则

内容默认处理升级为公式块的条件
变量、符号、条件 行内，如 $x$、$x \to 0$、$n \ge 1$。 不升级。
短等式/短不等式 行内，如 $a^2+b^2=c^2$、$|f'|\le M$。 长度超过 34 个字符，或含多个等号/换行。
简单分式 优先行内，如 $\frac{\sin x}{x}$ 出现在解释句中。 分子/分母较长，或作为最终答案/核心结论单独出现。
求和、积分、极限 短条件可行内说明，但展示公式中的 \lim、\sum、\prod 必须使用上下限结构。 出现 $$...$$、嵌套分式、复杂上下限、表达式超过 34 字符时升级为展示公式。
矩阵、分段函数、aligned 公式块。 始终公式块，因为行内会破坏阅读和布局。
连续推导 轻量 derivation 组。 连续 2 行以上等式，或每行都以 =、\le、\Rightarrow 串联。

5.5 AI 对话公式渲染 profile

项聊天规则笔记详情规则
展示公式容器 透明背景、无边框、上下 4-6px 间距；视觉上像回答中的公式条。只允许横向滚动，滚动条使用主色细条，隐藏纵向滚动。 允许弱背景和细边框，作为知识点重点块。
上下分式 必须用 KaTeX 真排版。行内简单分式保持 inline；展示公式使用 displayMode: true 或 \displaystyle。 同样用 KaTeX；长公式可增加横向滚动容器和弱背景。
算子上下限 AI 聊天中的展示公式必须启用 displayMode: true；必要时 normalizer 对 \lim_{...}、\sum_{...}^{...} 补 \limits 或 \displaystyle，保证上下结构。 笔记详情同样要求展示公式上下结构；行内公式可保持紧凑，但不得把显式 $$...$$ 的上下限压到右侧。
行内分式 优先 displayMode: false，必要时 normalizer 将简单行内 \frac 转成 \tfrac，避免撑高聊天气泡行高。 可保留 \frac，笔记详情行高更宽松。
多行推导 轻量左线 + 紧凑行距，不给每行加背景；行注释默认隐藏或极弱显示。 可显示行注释，使用弱背景帮助复习扫描。
复杂环境 aligned/cases/matrix 独立公式条，限制最大高度，内部横向滚动。 独立公式块，可给更多留白。
fallback 不要显示大红错误块；用等宽/数学字体显示原始 LaTeX，保持透明背景和小字号。 可显示轻提示，说明该公式未渲染。

5.6 复合 LaTeX 最佳显示需求

复合公式不能只做到“能渲染”，还要做到“数学视觉上符合用户预期”。例如正态分布密度函数中，\exp(-\frac{...}{...}) 虽然合法，但在手机聊天气泡里会显得像代码函数调用；显示层应优先转成指数结构，并按场景选择最适合阅读的等价形式。

核心要求：Normalizer 输出的是渲染用 LaTeX，不回写数据库。AI 原文、OCR 原文、用户编辑内容仍按原始文本保存；UI 在渲染前生成 renderLatex，同时保留 rawLatex 用于复制、编辑和排错。

rawLatex:
f(x)=\frac{1}{\sigma\sqrt{2\pi}}\exp(-\frac{(x-\mu)^2}{2\sigma^2})

noteDisplayLatex:
f(x)=\frac{1}{\sigma\sqrt{2\pi}}e^{-\frac{(x-\mu)^2}{2\sigma^2}}

chatDisplayLatex:
z=\frac{x-\mu}{\sigma},\quad f(x)=\frac{1}{\sigma\sqrt{2\pi}}e^{-\frac{z^2}{2}}

上面三者数学等价，但 UI 取舍不同：笔记详情可以展示完整上下分式；AI 聊天气泡空间更窄，应先提取 z，再用紧凑指数，避免指数里再嵌一个过高的大分式。

需求规则示例
指数函数 当 \exp(...) 的内容是单个数学表达式，尤其含负号、平方、分式时，显示层优先规范为 e^{...}。聊天中进一步优先选用等价紧凑形，不把大分式塞进指数。 \exp(-\frac{(x-\mu)^2}{2\sigma^2}) → 笔记 e^{-\frac{(x-\mu)^2}{2\sigma^2}}；聊天优先 z=\frac{x-\mu}{\sigma} + e^{-\frac{z^2}{2}}
场景型等价改写 同一个数学表达式允许有不同显示形态：笔记详情追求完整标准式，AI 对话追求窄屏可读式。等价改写只允许在确定数学含义不变时发生。 正态密度函数在聊天中推荐先写 z=(x-\mu)/\sigma，再写 e^{-z^2/2}，比 e^{-\frac{(x-\mu)^2}{2\sigma^2}} 更不压迫行高。
复合分式 展示公式中的分式使用 \dfrac 或 KaTeX displayMode；行内简单分式可用 \tfrac，避免撑高行距。 \frac{1}{\sigma\sqrt{2\pi}} 在密度函数展示公式中必须是上下结构。
括号尺寸 复合公式中的大括号使用 \left / \right 或由 KaTeX 自动处理；不要显示普通过小括号包住高分式。 e^{-\left(\frac{x-\mu}{\sigma}\right)^2/2}
根号 根号必须由 KaTeX 渲染为完整 radical：根号符号高度覆盖被开方项，顶部横线完整覆盖 2\pi。Normalizer 可把 sqrt(2*pi) 修为 \sqrt{2\pi}。 \sigma\sqrt{2\pi} 中 2\pi 必须在根号横线下方，不显示成 σ√(2π) 的普通字符串。
等号基线 复合公式不能按普通文本 baseline 排列。等号左侧、系数分式、指数项应由 KaTeX 按数学轴线居中对齐；渲染失败时只显示原始 LaTeX 文本，不再实现手写分式/根号/指数结构。 f(x)=\frac{1}{\sigma\sqrt{2\pi}}e^{-z^2/2} 中等号应对齐右侧公式整体中线。
算子极限 展示公式中的 \lim 必须显示为“lim 在上、条件在下”的上下结构。实现上依赖 KaTeX displayMode: true，或补成 \displaystyle\lim_{x\to0} / \lim\limits_{x\to0}。 $$\lim_{x\to0}\frac{\sin x}{x}=1$$ 不允许渲染成 lim 右下角小标。
语义压缩 聊天中优先使用最清晰的数学等价形式，而不是最冗长的程序式写法。必要时把复杂公式拆成“定义一句 + 公式条 + 解释一句”。 先写 X\sim N(\mu,\sigma^2)，再给密度函数，不把所有信息塞进一个巨大公式块。

六、分阶段落地

Stage 0

清理输入: normalize + parse

先修输入解析，不再扩展原生公式渲染。

修正 MathTextParser.ets 的 C 风格 for；增加 LatexTextNormalizer；把 $x \to 0$、$\frac{\sin x}{x}$、$a^2+b^2=c^2$ 这类短公式保留为行内 token。公式视觉不在这一层处理，统一交给 KaTeX。

验收短公式不再独占一行；同一段内多个短公式仍保持一个连续段落；/frac 可修成 \frac；输出可直接交给 KaTeX。
截断如果 Web/KaTeX 暂缓，只保留原始 LaTeX 文本显示，不做手写公式排版。
Stage 1

RichMath 类型、清洗、解析

先建立统一数学语义层，不急着接业务页面。

paragraph(tokens: text | inlineMath)
displayFormula(latex, raw)
derivation(rows: displayFormula[])
验收5 类笔记样例都能解析出稳定块；普通段落内公式块数量明显减少；连续等式合并为 derivation。
截断解析层是纯函数，可单独调试，不影响 UI。
Stage 2

HTML Builder + 本地 KaTeX

实现真正公式排版，但先离线验证 HTML。

生成一段完整 HTML，一条聊天消息或一个笔记分区对应一个 Web 上下文。不要每个小公式一个 Web，否则滚动和性能都会变差。

验收行内 \frac{a}{b} 不打断句子；展示公式中的分式是上下结构；aligned 和多行推导能显示；长公式横向滚动。
截断如果 ArkUI Web 调试卡住，HTML 仍可在浏览器中验证。
Stage 3

RichMathRenderer 组件

封装 Web/KaTeX 加载、缓存、高度和原始文本兜底。

第一版不要追求复杂 JS bridge。可以先用估算高度 + 最大高度 + 内部滚动；KaTeX 渲染失败时切到原始 LaTeX 文本。不要实现手写分式、根号、指数、上下限。

实际落地采用更轻的方式：Web 加载 rawfile/render.html 后，ArkTS 通过 runJavaScript("render(...)") 传入 Markdown/LaTeX；JS 渲染完成后返回 scrollHeight，组件更新自身高度。这样只保留公式内部横向滚动，不出现纵向滚动条。

验收空内容不占高度；渲染失败不白屏；复杂公式不撑破父容器。
截断组件可先挂在独立测试页或临时样例页。
Stage 4

先接 AI 对话

聊天内容短，反馈快，适合先验证自然混排。

修改 ChatBubble.ets 两处调用。AI 气泡启用完整 RichMath 的 chatAi profile：行内优先、展示公式为轻量公式条、上下分式必须真排版；用户气泡可以先 compact 模式；复制仍复制原始文本。

验收20 条含公式消息滚动不卡；短公式和文字自然同行；单条解释消息不会因为 3-5 个短公式变成 3-5 个独立公式块；展示公式没有重卡片感；上下分式、根号、求和能真实排版；Copy 结果仍是原始 LaTeX。
截断若性能不稳，先只给 AI 气泡启用 KaTeX；用户气泡显示原始 LaTeX 文本。
Stage 5

再接笔记详情

笔记较长，应在 MarkdownRenderer 的 block 层接入，不做整页 Web。

NoteSection.ets 继续只调用 MarkdownRenderer。在 MarkdownRenderer 内：heading/list/quote/code 仍原生渲染，paragraph/formula 才进入 RichMath。

验收概念、定理、公式、证明题、计算题详情都能自然展示公式；公式块数量克制，正文说明不被频繁打断；编辑器保存后的 Markdown 仍能显示。
截断某个 section 渲染失败只 fallback 该 section，不影响整页详情。
Stage 6

回归与收尾

稳定后再考虑废弃旧主路线。

检查 rg "MathTextRenderer|splitMathText"。如果只剩 wrapper 或无业务引用，再考虑降级旧组件职责；不要把旧的手写公式渲染继续发展成第二套实现。

验收DevEco Studio GUI 编译；真机检查聊天、笔记详情、编辑保存、长公式滚动。
截断Web/KaTeX 不稳定时只显示原始 LaTeX 文本，不上线手写公式排版。

风险影响处理
ArkUI Web API 版本差异编译或运行失败第一版使用最小 Web 能力；失败显示原始 LaTeX 文本；不要依赖 API 11+ 特性。
Web 太多导致滚动卡顿聊天列表和详情页性能差一条消息/一个 section 一个 renderer；加 HTML 缓存；限制 maxHeight。
Markdown 与数学解析重复公式被错误拆块或代码块被渲染Markdown 做外层，RichMath 只处理 paragraph/formula；code 永远不进公式渲染。
公式块过多手机端阅读被频繁打断，像代码清单而不是讲解默认行内；只有超过阈值、显式展示、矩阵/cases/aligned、多行推导才块化；聊天块使用透明公式条。
聊天公式上下结构不清楚为了减少块而把分式压成难读的一行文本简单行内分式可用 \tfrac，重点公式必须用 KaTeX display math 真分式；减少容器重量，不降低公式排版质量。

数据库污染编辑/检索/AI 再结构化变复杂严禁把 HTML、SVG、图片、KaTeX 输出写回 knowledge_unit。

八、验收样例

输入文本期望渲染覆盖点
当 $x \to 0$ 时，$\sin x \sim x$，因此可替换。 两个短公式嵌在同一句中文内，不独立成块，段落保持一行或自然换行。 行内公式
所以 $\frac{\sin x}{x}$ 的极限为 1。 简单分式留在正文里，不因为有 \frac 就自动块化。 简单分式行内
$$\lim_{x\to0}\frac{\sin x}{x}=1$$ 显式展示公式才独立成轻量公式条；lim 的 x\to0 在正下方，分式也是上下结构，超宽时横向滚动。 展示公式、极限上下限、分式
若 $X \sim N(\mu,\sigma^2)$，则密度函数为 $$f(x)=\frac{1}{\sigma\sqrt{2\pi}}\exp(-\frac{(x-\mu)^2}{2\sigma^2})$$ $X \sim N(\mu,\sigma^2)$ 保持行内；密度函数作为轻量公式条。笔记详情显示完整标准式，根号有横线、两个分式均为上下结构；AI 聊天优先拆成 z=(x-\mu)/\sigma + f(x)=\frac{1}{\sigma\sqrt{2\pi}}e^{-z^2/2}，不得直接展示 exp(...)。 正态分布、exp 规范化、根号、场景化复合公式
令 $Z=\frac{X-\mu}{\sigma}$，则 $Z\sim N(0,1)$。 标准化公式整体留在正文中，简单分式不自动升级成公式块。 正态分布标准化、简单分式行内
\begin{aligned} a&=b+c \\ d&=e+f \end{aligned} 作为一个推导/对齐组显示，不拆成多个大卡片。 aligned、多行推导
```ts\nconst x = "$not math$"\n``` 代码块原样显示，不触发公式渲染。 Markdown 与数学边界
/frac{1}{2} + \sqt{x} Normalizer 修正为 \frac{1}{2} + \sqrt{x} 后再渲染，并记录 issue。 OCR/AI 错误修复
