TypeClassifier 与 KnowledgeModel 数据契约

说明当前程序里“分类/学科谁判断、TypeClassifier 如何影响 KnowledgeModel、五类字段表、KnowledgeModel 最小单位、入库必填字段”。

2026-07-20

一句话结论

TypeClassifier 当前负责文本提取与轻量分类。 主生成链里 Dispatcher.dispatch() 只调用 recognizeText() 得到干净文本，不在调度层增加第二次分类调用。KnowledgeModel 保留最终智能分类：在没有外部 hint 时，它会短超时调用 TypeClassifier.classifyText() 获取五类/学科 hint，成功则参考，失败则继续生成笔记。

数据库当前不是五张分类表，而是统一写入一张 knowledge_unit 表；五类只决定 fields 应该按哪套结构化字段生成，再拼成 content 入库。类别暂时限制为五类：概念、定理、公式、证明题、计算题。

一、职责边界

模块输入输出职责
TypeClassifier DispatchPayload: text / image / file ClassificationResult: type / subject / chapter / confidence / ocrText 做 OCR 或文本提取、清洗噪声；classify() / classifyText() 用 LLM 识别五类与学科，失败时规则兜底。
KnowledgeModel 最小输入是清洗后的 ocrText: string KnowledgeUnit 调用 LLM 自主判断最终学科 subject 和五类 category；没有外部 hint 时，会先短超时获取 TypeClassifier hint，生成结构化 fields，再转换为数据库主模型。
NoteDao KnowledgeUnit RDB rowId / KnowledgeUnit 查询结果 只负责 KnowledgeUnit 与 knowledge_unit 表互转，不做分类推理。

二、处理流程

1. 输入 UI 明确点击“保存/生成笔记”后调用 capture()，传入文本、图片路径或文件路径。
2. 文本化 Dispatcher.dispatch() 调用 TypeClassifier.recognizeText()，只得到清洗文本。
3. 分类 hint KnowledgeModel.resolveClassificationHint() 短超时调用 classifyText()，得到五类/学科参考。
4. 结构化 KnowledgeModel.callAi() 参考 hint，但按正文最终判断 category/subject 并生成 fields。
5. 入库 转换成 KnowledgeUnit，写入 knowledge_unit。

三、KnowledgeModel 接受的最小单位

最小输入

KnowledgeModel.structure(
  ocrText: string,
  type?: string,
  subject?: string,
  chapter: string = ""
): Promise<KnowledgeUnit>

ocrText 是唯一必要输入。当前主链 Dispatcher.dispatch() 只传 ocrText，不额外传分类 hint，避免主调度被第二次分类阻塞。

可选 hint

type?: string
subject?: string
chapter?: string

这些参数保留给兼容调用方。即使传入，prompt 也明确让大模型可以参考但独立判断。

四、TypeClassifier 如何正向影响 KnowledgeModel

Dispatcher.dispatch(req)
  -> TypeClassifier.recognizeText(payload)
  -> KnowledgeModel.structure(ocrText)
     -> resolveClassificationHint(ocrText)
        -> TypeClassifier.classifyText(ocrText, 10000)
     -> callAi(ocrText, typeHint?, subjectHint?, chapterHint?, confidenceHint)

这条链路不改主调度能力：调度层只负责拿文本和调用 KnowledgeModel.structure()。分类影响发生在 KnowledgeModel 内部，是软 hint，不是硬覆盖。

只有外部明确传入 type，或者 TypeClassifier 的置信度达到 0.55，五分类才会进入结构化 prompt。学科只要不是 其它 且非空，就可以作为学科 hint。分类器失败、超时或返回低置信时，KnowledgeModel 继续独立生成笔记。

五、大模型必须返回的最小 JSON

{
  "category": "概念 | 定理 | 公式 | 证明题 | 计算题",
  "subject": "由大模型自主判断的学科名称",
  "title": "严谨标题或题目摘要",
  "tags": ["2-4 个中文关键词，不放学科名"],
  "difficulty": 1,
  "importance": 1,
  "fields": [
    {
      "key": "字段程序名",
      "label": "页面标题",
      "value": "结构化正文"
    }
  ]
}

category 必须是中文五类之一；subject 不限制枚举，由大模型根据题目内容自由判断。

六、五类调用哪张“字段表”

关键说明

这里的“表”是 结构化字段表 / Schema，不是 RDB 表。RDB 只有 knowledge_unit 一张主表。

category字段表 key落库方式
概念 definition / properties / examples / related_concepts 每个字段转为 ## label 分段，拼入 KnowledgeUnit.content。
定理 statement / conditions / conclusion / proof_sketch / applications 同上，字段本身不单独落 RDB 列。
公式 expression / parameters / applicable_range / derivation / notes 同上。
证明题 proposition / given / proof_process / key_insight / conclusion 同上；标题、难度、重要性会标记为建议用户确认。
计算题 problem / steps / answer / method_summary / common_mistakes 同上；标题、难度、重要性会标记为建议用户确认。

七、转换为 KnowledgeUnit 时的必填项

由 AI 直接贡献

title subject category tags difficulty fields

fields 不作为独立字段保存，而是生成 content 和 summary。

程序自动补齐

id createdAt updatedAt reviewStatus nextReviewAt intervalDays easeFactor repetitions source prerequisites related embedding userId version

这些字段在 toKnowledgeUnit() 或 fallback 路径中给默认值。

八、写入 knowledge_unit 表时什么是必填

RDB 层 NOT NULL 字段很多，但多数有默认值。实际 NoteDao.toBucket() 会把完整 KnowledgeUnit 全量写入。

列是否必须非空/非 null来源
id必须有值，主键。KnowledgeModel.uuid() 或 fallback 生成。
title必须有值。AI 返回；fallback 用 OCR 首行或“笔记/概念”。
content必须非 null，可为空字符串。contentFromFields()，字段分段 + 原文。
summary必须非 null，可为空字符串。summaryFromFields()。
tags必须非 null，JSON 字符串。NoteDao.stringifyArray(unit.tags)。
subject必须非 null，可为空字符串。AI 自主判断；失败 fallback 为 其它，旧数据读取时允许为空。
category必须非 null，推荐五类之一。AI 返回五类；失败 fallback 默认为 概念。
difficulty必须非 null。AI 1-5 转 DifficultyLevel；fallback 为 MEDIUM。
source必须非 null，可为空字符串。chapter 或 camera_capture。
created_at / updated_at必须有时间戳。程序用 Date.now()。
review_status必须非 null。新笔记默认为 new。
next_review_at必须有时间戳。默认创建时间 + 1 天。
interval_days / ease_factor / repetitions必须非 null。默认 1 / 2.5 / 0。
prerequisites / related / embedding必须非 null，JSON 字符串。当前默认空数组。
user_id必须非 null，可为空字符串。当前默认空字符串。
version必须非 null。默认 1。

九、实现上要守住的规则

1Dispatcher.dispatch() 不承载分类 LLM 调度，只保持 OCR/文本提取 → KnowledgeModel.structure() 的主生成链。

2TypeClassifier 负责轻量分类和兜底，不生成结构化笔记。

3KnowledgeModel 可以参考分类 hint，但最终分类、学科、字段内容仍由结构化 LLM 按正文判断。

4category 暂时限制为中文五类；不要返回英文枚举。

5subject 不做固定枚举，让大模型根据题目自主判断，无法判断时为 其它。

6五类对应的是结构化字段表，不是数据库分表。

7入库前必须构造完整 KnowledgeUnit；RDB 写入统一走 NoteDao.toBucket()。

8UI 保留明确“保存/生成笔记”动作调用 capture()；拍照分析对话只识别/分析，不自动入库。
