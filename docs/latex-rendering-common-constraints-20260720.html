MathMind LaTeX 生成与渲染共同约束

适用范围：TypeClassifier、KnowledgeModel、AgentChatService、笔记详情页、AI 对话框、首页/学科块小字预览。目标是让 AI 输出、数据库存储和 KaTeX 渲染使用同一套格式边界，避免红色错误文本、美元符号外露、裸反斜杠和公式块泛滥。

2026-07-20 · Common Constraints
唯一渲染核心 公式只交给 KaTeX，旧手写分式/根号渲染不再作为主路径。
最小存储单位 数据库保存规范 Markdown + LaTeX 原文，不保存渲染后的 HTML。
生成端责任 LLM 必须输出合法 delimiter，不把裸 LaTeX 混入普通文本。
渲染端责任 含公式内容整段进入 KaTeX WebView，UI 可做容错归一化，但不猜测错误公式语义。

1. 共同边界

对象 必须遵守 禁止事项
KnowledgeModel 生成 `title`、`summary`、`content` 时，数学符号必须使用 `$...$` 或 `$$...$$`。 禁止输出 `\int`、`\frac`、`\sqrt`、`\lim` 这种裸反斜杠公式。
AgentChatService 回答中短公式用 inline math，重点公式用 display math。 禁止在 display math 内再次嵌套 `$...$`。
数据库 保存规范 Markdown 文本。`content` 可以包含标题、段落、列表、公式。 禁止保存 KaTeX 生成的 HTML、CSS class 或 WebView 私有标记。
UI 渲染 详情页、对话框、预览小字都通过统一公式检测进入 KaTeX。详情正文只要含公式，就整段 Markdown 作为一个渲染单元，不再按标题/段落拆多个 WebView。 禁止恢复旧的 Text 拼接分式、手写根号、手动上下标渲染；禁止在详情正文里混用 native 结构先展示、公式 WebView 后补齐的分段加载模式。
渲染缓存 缓存只存在 UI 进程内，key 使用 `profile + forceDisplay + normalizedMarkdown hash`，value 保存已渲染 HTML 与高度。 禁止把缓存 HTML 写入 RDB；禁止用整段正文原文直接当缓存 key；禁止按 noteId 作为唯一缓存依据。

2. LaTeX 写法硬约束

行内公式

用于短变量、短条件、句内数学对象。

积分变量为 $x$，积分常数为 $C$。
当 $n \neq -1$ 时公式成立。

禁止裸行内公式

裸反斜杠会被 Markdown 当普通文本处理，或被容错逻辑误判。

积分变量为 \x，积分常数为 \C。
当 \n \neq -1 时公式成立。

展示公式

单独成行、复杂、有分式/积分/极限的公式必须使用 `$$...$$`。

$$
\int x^n\,dx = \frac{x^{n+1}}{n+1} + C \quad (n \neq -1)
$$

禁止嵌套美元符号

这是当前红色公式的主要来源：外层被当公式时，内层 `$...$` 破坏解析。

\int x^n, dx = \frac{x^{n+1}}{n+1} + C \quad ($n \neq -1$)

3. 推荐公式模板

场景 推荐输出 说明
幂函数积分 $$\int x^n\,dx = \frac{x^{n+1}}{n+1} + C \quad (n \neq -1)$$ `dx` 前使用 `\,`，条件不要再包 `$...$`。
指数函数积分 $$\int a^x\,dx = \frac{a^x}{\ln a} + C \quad (a > 0,\ a \neq 1)$$ 多个条件放在同一个公式环境内。
极限 $$\lim_{x \to 0}\frac{\sin x}{x}=1$$ `\lim_{...}` 必须作为一个整体进入 KaTeX。
正态分布 $$f(x)=\frac{1}{\sigma\sqrt{2\pi}}\exp\left(-\frac{(x-\mu)^2}{2\sigma^2}\right)$$ 分式、根号、指数括号交给 KaTeX，不做手写渲染。
段落混排 当 $x>0$ 时，$\ln x$ 有定义；积分常数记为 $C$。 一句话里的短公式全部使用 inline math。

4. 生成端 Prompt 约束

下面这段应进入 KnowledgeModel 与 AI 对话 prompt 的“数学格式要求”。

数学公式输出规则：
1. 行内短公式必须写成 `$...$`，例如 `$x$`、`$C$`、`$n \neq -1$`。
2. 独立复杂公式必须写成 `$$...$$`，例如 `$$\int x^n\,dx = ...$$`。
3. 不要输出裸 LaTeX 命令行，例如不要直接输出 `\int ...`、`\frac ...`。
4. 不要在 `$$...$$` 内再写 `$...$`。
5. 公式条件放在同一个公式环境里，例如 `\quad (n \neq -1)`。
6. 文本解释和公式分开：先写一句说明，再写展示公式。

5. 渲染端容错边界

可以自动修复

UI 可以修复常见但语义明确的问题。

\int x^n, dx = ... ($n \neq -1$)
→
$$\int x^n\,dx = ... \quad (n \neq -1)$$

只能降级显示

括号不闭合、命令拼错、公式语义缺失时，UI 不猜测数学意图。

$$
\frac{x+1
$$

处理：保留原文或显示错误态，不能自行补分母。

6. 数据流约定

OCR 只负责识别文本，尽量保留原始公式字符。
TypeClassifier 只判断题型/学科，不改写公式正文。
KnowledgeModel 结构化笔记，并按本约束规范化 Markdown + LaTeX。
RDB 保存规范文本、分类、学科、标签、复习字段。
UI 按内容类型选择整段 KaTeX 或 native 文本，并使用进程内渲染缓存。

7. 当前问题复盘

错误来源：裸展示公式 + 内嵌美元符号
红色原文通常来自这种输入：
\int x^n, dx = \frac{x^{n+1}}{n+1} + C \quad ($n \neq -1$)
它应被生成端直接写成：
$$\int x^n\,dx = \frac{x^{n+1}}{n+1} + C \quad (n \neq -1)$$
错误来源：段落行内公式没有进入 KaTeX
段落中的 `$x$`、`$C$`、`$n \neq -1$` 必须被公式检测捕获。UI 的检测条件必须包含单美元符号和反斜杠命令。

8. 验收标准

页面 必须通过
AI 对话框 复杂公式不露出反斜杠原文；行内 `$...$` 不显示美元符号；公式区域只有横向滚动条；同一条消息内公式不分多个 WebView 闪现。
笔记详情页 正文、摘要、推导段落中的行内公式和展示公式都能渲染；含公式正文作为一个整体加载，不出现标题/段落结构先显示、公式内容后补齐的明显割裂。
首页笔记小字 包含公式的预览不再显示红色错误文本；普通文本仍走原生截断；公式预览不撑开卡片高度。
学科块小字 标题或预览含公式时进入 KaTeX compact preview；不撑开卡片高度。
重复进入同一笔记 第二次进入同一内容时命中进程内缓存，布局先使用缓存高度，WebView 只回填已渲染 HTML，不重复执行 KaTeX 解析。
结论： 以后判断问题时先看源文本是否符合本约束。若源文本符合约束仍渲染失败，归为 UI 渲染 bug；若源文本裸写 LaTeX、嵌套 `$...$`、括号不闭合，归为生成端格式 bug，UI 只做有限容错。
